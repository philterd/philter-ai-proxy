# Changelog

All notable changes to this project will be documented in this file.

## [2.0.0] - Unreleased

A rewrite in Java that redacts in-process with Phileas, with no Philter backend. 2.0 does not read 0.x configuration files.

- Redaction with Phileas inside the proxy. Person names are found with the `ph-eye-pii-en-small` PhEye model, included in the Docker image and run in-process. All the text of a request is redacted together, against one policy.
- Policies are native Phileas policies, stored in the proxy's SQLite database and managed with a Philter-compatible policy API under `/admin/api/policies`. A built-in `default` policy finds person names, SSNs, and email addresses. Policies may not name a PhEye service, generators, or files and environment variables the deployment has not allowed.
- API keys, always required, managed under `/admin/api/keys`: roles (`admin`, `proxy`), scopes on providers, models, and paths, and a bound policy. Keys are stored as SHA-256 hashes.
- Contexts keep replacements consistent across requests, stored in the database with the original values encrypted (AES-256-GCM).
- Providers: OpenAI (chat, Responses, completions, embeddings, moderations, image generation, speech), Azure OpenAI (with Entra ID), OpenAI-compatible providers, Anthropic, Gemini, Vertex AI, Ollama, and Bedrock Converse. Request fields the proxy does not redact are forwarded unchanged. Requests without a body, such as `GET /v1/models`, are forwarded.
- Response scanning (`redact`, `block`, `flag`) for every provider, including streamed responses, which are scanned as they arrive. Content parts, refusals, tool-call arguments, and reasoning text are scanned, and `logprobs` removed under `redact` and `block`. A response that cannot be scanned is refused rather than returned unscanned.
- Requests with a body to an endpoint the proxy cannot redact, and, with response scanning on, requests whose responses it cannot scan, are refused with `400 unsupported_endpoint` by default. `unsupported-endpoints: forward` forwards them. The request path is decoded once for routing, scopes, and classification, and path scopes match on segment boundaries.
- Fields added to redaction and response scanning after the 2.0 security review: Responses `prompt.variables`, tool outputs given as parts, MCP and shell call outputs, and reasoning text; chat `prediction`, refusal parts, and the `reasoning_content` of OpenAI-compatible servers; Anthropic message batches and search results; Bedrock `guardContent`; Gemini code execution parts; Ollama `suffix` and `template`; and integers of five or more digits in tool arguments. Gemini `logprobsResult` and Ollama `context` and `logprobs` are removed under `redact` and `block`.
- Responses read for scanning are capped (`proxy.limits.max-response-body-bytes`, and per line and event in streams); a Bedrock exception message ends a scanned stream. A key with a bound policy skips routes that match on a header. Azure OpenAI's model scope checks the deployment in the path. The audit log keeps at most 256 characters of the model and can be pruned with `proxy.audit.retention-days`. The Helm chart's probes are TCP checks when mTLS is on.
- Lower-severity hardening from the review: binary responses are returned unscanned only from speech; 3xx responses are refused under scanning; scanned streams drop unscanned comment, `id:`, and `retry:` text and refuse unusual event names; interrupted streams are ended with an error and audited; key path scopes see an OpenAI-compatible provider's prefix; Vertex AI paths must name the configured project; OpenAI-family and Ollama requests that spell a redacted field in another case are refused; policies are encrypted at rest and contexts no longer store original values; redaction has a timeout (30 s) and concurrency a default limit (200); the Helm chart gains an optional NetworkPolicy and no longer mounts the service account token; examples publish the metrics port on loopback only.
- Every Ollama path (`/api/...`) goes to Ollama. Paths other than `/api/generate` and `/api/chat`, such as `/api/tags`, were sent to OpenAI. Found by the new contract tests (`test/contract/`), which run each provider's official SDK against the proxy.
- Bedrock InvokeModel (`/invoke` and `/invoke-with-response-stream`) for Anthropic Claude models, as used by the Anthropic SDK's Bedrock client, and `/invoke` for Amazon Titan and Cohere embedding models. Every `/model/<id>/...` path goes to Bedrock; InvokeModel paths were sent to OpenAI. Bedrock's `X-Amzn-Bedrock-*` headers, such as a guardrail, are forwarded and signed, guardrail traces are removed from scanned responses, and errors carry the `x-amzn-ErrorType` header and top-level `message` AWS SDKs read.
- A request forwarded under `unsupported-endpoints: forward` has its response returned unscanned, as documented, even when the route scans responses. It was read with the provider's dialect, which, for example, dropped every progress line of a streamed Ollama `/api/pull`.
- Fixes from a review of the provider additions: a request to an endpoint the proxy does not redact is refused for providers it authenticates to with its own credential (Vertex AI, Bedrock, Azure with Entra ID) even without a body, so a proxy key cannot use that credential on other endpoints; the case-variant check also catches `model` and `name`, and the long s and Kelvin sign that Go folds to `s` and `k`; Vertex AI `countTokens` `instances` are redacted; legacy Claude `prompt` bodies on Bedrock are redacted, their `completion` scanned, and their streams refused under scanning; any `...GenerateContent` method goes to Gemini; and a Bedrock stream the proxy ends carries an AWS error message that SDKs raise.
- Gemini and Vertex AI grounding metadata is scanned: the answer passages citations quote, search and retrieval queries, rendered search suggestions, and the titles and text of grounding sources. Under `flag`, a Bedrock InvokeModel stream chunk the proxy cannot decode is forwarded as it came, as documented, instead of ending the stream.
- Gemini `:countTokens`, `:embedContent`, and `:batchEmbedContents` are redacted, and Vertex AI `:countTokens`. Gemini methods are routed to Gemini by name, so `/v1/models/...:embedContent` no longer goes to OpenAI, and every Vertex AI `/projects/` path goes to Vertex AI, checked against the configured project.
- Fixes from a review of the documentation: an admin API or health request that no endpoint accepts (an unknown path, or the wrong method or content type) is answered `404` instead of being forwarded to OpenAI as provider traffic; a request without a body whose response is not scanned is forwarded even when its route's policy cannot be used; and Anthropic citations (`cited_text` and source titles) are scanned in buffered responses as they were in streams, and source titles in streams too.
- Ollama embeddings (`/api/embed`, and the older `/api/embeddings`) are redacted, and `/api/show`, which carries no conversation text, is forwarded, so front ends such as Open WebUI work under the default `unsupported-endpoints: reject`.
- Requests carrying images, audio, video, or files, which the proxy does not redact, are refused with `400 media_not_allowed` by default. `media: forward`, in `proxy.defaults` or on a route, forwards them with the media unchanged.
- HTTPS by default in the image with a self-signed certificate generated at startup; your own certificate and mutual TLS through `server.ssl.*`.
- An audit log of metadata only, in the database, on standard output, and optionally in a file; Prometheus metrics named `philter_proxy_*`; OpenTelemetry tracing with the trace ID in the audit log; `/livez`, `/readyz` (once loading the configured policies and their models has finished), and `/health`.
- `--version` and `--validate-config`. The proxy refuses to start with an encryption key other than the one its database was created with.
- A Helm chart and plain manifests for a single replica with a persistent volume, a Grafana dashboard, and a k6 load-test harness.
- Routing, failover, rate limiting, response caching, and token or spend accounting remain out of scope. See [Using with an AI Gateway](docs/docs/ai-gateway.md).

## 0.2.0 and earlier

The Go versions, which sent each text to a Philter instance for redaction. Tagged `0.1.0` and `0.2.0`.
